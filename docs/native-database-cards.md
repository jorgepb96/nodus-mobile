# Native database cards — source stage

iPhone boards select one real group and display its cards vertically; iPad retains adjacent lanes. Select/status options are grouped by stored IDs, including duplicate labels, configured empty lanes, direction and capacity limits. People retain canonical identities and readable labels. Saved subgroups and card properties remain consultable.

Gallery sizing follows saved preferences and the device width. Cards display actual vault-owned attachment or page-cover bytes through the existing private file contract. The original remains available in the native row inspector. Visible raster covers decode to bounded previews and disappearing cards release their pixels. SVG/GIF use the isolated existing image renderer; fit is restricted to cover/contain. A failed file load exposes its real accessibility issue rather than pretending the source has no cover.

Date, location and people values use the canonical property structures for presentation; stored strings stay unchanged. Advanced database presentations refresh after native property edits.

Prepared `DatabaseCardPresentationTests` cover real lane identities, capacity, empty groups and structured display. Offline saved filters now use the complete selected-source engine described in [offline-database-container.md](offline-database-container.md). **Not executed for this source revision.** Compilation, iPhone/iPad screenshots, downloaded cover availability, large galleries, page-content previews and source-specific linked view settings remain final acceptance/source work. This is not proof of full database parity.
